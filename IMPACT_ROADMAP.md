# From a learning collection to measured public benefit

**Working principle:** start with a problem that intended users recognize, define what improvement means, and publish evidence that another group can reproduce. More links, stars, or demonstrations do not establish impact by themselves.

## Three proposed pilots

| Pilot | Intended users | Baseline | Prototype | Main measures |
| --- | --- | --- | --- | --- |
| Less waste in small-scale fabrication | Maker labs and local manufacturers | Existing panel layout and assembly workflow | Material-aware parts, nesting, and supervised simulated handling | Material per usable part, scrap, failed joints, assembly time |
| Accessible control of a simple task | People who encounter access barriers | Their current interaction method | Keyboard-accessible interface plus a low-voltage switch | Completion rate, input errors, assistance required, user-reported effort |
| Traceable local material reuse | Community workshops and reuse groups | Existing inventory and sorting practice | Batch identities, condition records, and reuse events | Traceable batches, missing records, reused mass, recording effort |

These pilots are proposed, not completed studies. Define targets with partners before collecting outcomes. Participant involvement needs suitable consent and a clear plan for what data will be retained and shared.

## Work packages

| Phase | Concrete work | Exit evidence |
| --- | --- | --- |
| Define | Interview intended users, select one task, document constraints | One problem statement, baseline workflow, agreed primary outcome |
| Reproduce | Run the relevant lessons on a second machine | Environment record and independent successful run |
| Prototype | Implement the smallest usable intervention | Runnable artifact, costs, known failures, direct baseline comparison |
| Pilot | Test repeated tasks under a recorded protocol | Raw measurements, missing-data record, failures, user feedback |
| Replicate | Ask another workshop to repeat the procedure | Reproduction result and documented differences |
| Scale | Package training, maintenance, and ownership arrangements | Operating cost, support load, repair process, local adaptation evidence |

## Evaluation template

Record the following before an experiment:

1. Intended user and task.
2. Primary outcome, unit, and direction of improvement.
3. Baseline and candidate; variables held constant.
4. Trial count and justification; sampling and stopping rules.
5. Calibration, uncertainty, and missing-data treatment.
6. Failure and intervention definitions.
7. Training/evaluation separation where learning is used.
8. Cost, maintenance, accessibility, and context limitations.

Publish both improvements and failures. Use task-level paired comparisons when appropriate; choose statistical analysis to match the design rather than treating a single successful run as proof.

## A useful contribution ladder

- **Learning:** someone can complete the lesson.
- **Reproducibility:** a second person obtains comparable results.
- **Technical benefit:** the candidate improves a defined baseline.
- **User benefit:** intended users experience the agreed improvement.
- **Scale:** independent groups can maintain and adapt the system at acceptable cost.

The current archive supplies learning material and tested local examples. The later levels require new evidence.
